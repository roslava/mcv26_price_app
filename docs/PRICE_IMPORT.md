# Импорт прайс-листа XLSX

Этот документ описывает актуальный контракт `UploadValidator`, `PriceImporter`, `DraftVersionImporter` и admin upload endpoint.

## Файл и контейнер

Принимается только имя с расширением `.xlsx` без учёта регистра. Максимальный размер — `10 * 1024 * 1024` байт (10 МиБ). Пустой файл отклоняется.

После копирования во временный managed `.xlsx` проверяются:

- MIME через `finfo`, если extension доступен; разрешены OOXML/ZIP и несколько совместимых MIME;
- сигнатура ZIP `PK\x03\x04`;
- целостность открытия через `ZipArchive`;
- наличие `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`;
- результат `PhpSpreadsheet\IOFactory::identify()` равен `Xlsx`.

Макросы `.xlsm`, старый `.xls`, CSV и переименованный произвольный ZIP контракту не соответствуют.

## Листы

PhpSpreadsheet открывает книгу с `setReadDataOnly(false)`, чтобы видеть формулы. В книге должен быть ровно один непустой лист. Полностью пустые дополнительные листы не учитываются. Имя листа не проверяется.

Непустым считается лист, где хотя бы одна cell coordinate имеет значение, отличное от `null` и пустой строки.

## Строки 1–2

### A1 — заголовок

A1 после `trim()` должен быть непустым. Содержимое сохраняется как `price_versions.title`.

Дата ищется регулярным выражением как первая подстрока вида `д{1,2}.м{1,2}.гггг`, допускаются пробелы вокруг точек. Затем дата строго валидируется в UTC. Например, `Прайс от 30.08.2026` даёт `2026-08-30`. Если даты нет или она календарно неверна, импорт продолжается с `price_date = null`.

### A2:D2 — заголовки

Ожидаются значения:

| Ячейка | Точное значение после нормализации пробелов |
|---|---|
| A2 | `№ услуги` |
| B2 | `Код услуги` |
| C2 | `Наименование услуги` |
| D2 | `₽` |

Для сравнения выполняются `trim()` и замена любой последовательности whitespace одним пробелом. Регистр и символы должны совпадать.

## Строки с третьей и далее

Для каждой строки сначала читаются A:D и проверяется отсутствие данных в E и последующих колонках до highest data column.

### Пустая строка

A:D равны `null` или `''`. Строка игнорируется.

### Раздел

- A — непустая PHP-строка;
- B, C, D — строго `null`.

Значение A становится названием нового раздела. Форматирование/merge не является условием; важны фактические cell values. Если B:D содержат пустые строки вместо `null`, строка не распознаётся как раздел.

Импортер не запрещает два раздела подряд и проверяет только наличие хотя бы одного раздела и хотя бы одной услуги в книге в целом. Однако public reader требует минимум одну услугу в каждом опубликованном разделе; поэтому пустые разделы не следует создавать.

### Услуга

Все A:D должны быть заполнены:

- A — numeric положительное целое число;
- B — scalar, после строкового преобразования и `trim()` непустое;
- C — scalar, после строкового преобразования и `trim()` непустое;
- D — положительное число с максимум двумя десятичными знаками.

Услуга до первого раздела отклоняется.

Цена D преобразуется в целое число копеек без float arithmetic. Допустимый textual pattern:

```text
digits
digits.d
digits.dd
```

Десятичный разделитель — точка. Запятая, знак, пробелы внутри числа, exponent notation и более двух дробных цифр не допускаются. После `trim()` значение должно быть больше нуля и помещаться в `PHP_INT_MAX` копеек.

## Формулы

В A:D каждой строки данных начиная с третьей формулы запрещены. Ошибка возникает, если PhpSpreadsheet отмечает cell как formula или raw string начинается с `=`.

Код явно не выполняет такую проверку для A1/A2:D2, но их значения всё равно должны пройти проверки заголовка и точного текста. Не используйте формулы нигде в импортируемом шаблоне.

## Лишние данные и неоднозначные строки

Импорт отклоняет:

- частично заполненную услугу;
- строку, которая не является ни пустой, ни разделом, ни полной услугой;
- любые непустые значения в E и далее начиная с третьей строки;
- услугу до первого раздела;
- книгу без разделов или без услуг.

Стили, ширины колонок и оформление не участвуют в контракте.

## Дубликаты

Номера услуг отслеживаются глобально по всему листу. Повторный номер создаёт warning:

```text
code: duplicate_service_number
row: номер повторной строки
```

Импорт не прерывается, и обе услуги сохраняются. Дубли кодов, названий и разделов отдельно не проверяются. В БД номера/коды также не unique; unique constraints относятся только к позиции внутри родителя.

Admin upload endpoint не показывает список warnings пользователю, но считает файл успешно импортированным. CLI `bin/import-price.php` legacy-потока печатает warnings; `bin/import-draft.php` выводит только итоговые counts.

## Результат разбора

`PriceImporter` формирует массив schema version 1:

```text
schema_version: 1
imported_at: ISO-8601 timestamp
source:
  stored_filename
  title
  price_date: YYYY-MM-DD|null
currency: RUB
sections[]:
  name
  items[]: number, code, name, price_minor
stats: sections, items
warnings[]
```

При DB import каждый section становится `categories`, каждый item — `services`, а `imported_price_minor` и `current_price_minor` изначально равны `price_minor`.

## Duplicate-upload: актуальный алгоритм

Проверка выполняется после полной validation/parsing, поэтому совпадение hash не обходит контракт XLSX.

1. С исходного upload temporary path считается полный SHA-256 через `hash_file('sha256', ...)`.
2. Начинается DB transaction.
3. Выполняется `SELECT id, status, source_xlsx_sha256 FROM price_versions ORDER BY id FOR UPDATE`.
4. Из заблокированного набора выбираются совпадающие hashes и проверяются от самой новой версии к старой.
5. Для найденного draft вызывается полная проверка metadata, категорий, услуг, imported prices и сохранённого original hash. При успехе возвращается `existing_draft`.
6. Для published проверяется тот же граф, но цена XLSX сравнивается с `current_price_minor`. При успехе возвращается `unchanged_published`.
7. Если reuse невозможен, original сохраняется и создаётся новый draft.

Проверка original использует повторный `hash_file()` и `hash_equals()`. Если запись БД, граф или stored file не совпадают с ожидаемыми, импорт завершается ошибкой, а не доверяет одному hash в таблице.

### `source_xlsx_sha256`

Хранит полный 64-символьный SHA-256. После миграции 003 это обычный индекс `idx_price_versions_source_xlsx_sha256`, не unique: одинаковый исходный файл может легитимно породить разные версии.

### `source_identity`

Поле nullable и имеет unique index `uq_price_versions_source_identity`.

Обычная новая загрузка:

```text
upload:<первые 40 hex SHA-256>:<32 hex random nonce>
```

Nonce создаётся `random_bytes(16)`. Он нужен не вместо fingerprint, а для уникальности identity, когда тот же XLSX загружается после ручного изменения опубликованных текущих цен. Без nonce глобальная unique identity снова запрещала бы такой новый draft.

Legacy initial migration:

```text
initial:<полный SHA-256 XLSX>
```

Она идемпотентна по deterministic identity. Clone/restore версии создаются с `source_identity = null`, потому что не являются новой загрузкой файла.

При применении миграции 003 к старым строкам identity заполнялась отдельно: `initial:<sha256>` для строк с `source_json_sha256` и `draft:<sha256>` для остальных. Это migration backfill; новые обычные uploads используют nonce-формат выше.

### Блокировки и гонки

Locking read всех строк `price_versions ... FOR UPDATE` сериализует конкурентные импорты. Integration tests отдельно проверяют одновременную duplicate upload при наличии `pcntl`, socket pairs и тестовой MariaDB/MySQL.

Original записывается до завершения DB transaction. Если операция после записи падает, catch удаляет только что созданный файл. Уже существующий original при reuse не трогается.

## CLI

Создать или найти DB draft:

```bash
php -d auto_prepend_file=src/load_env.php bin/import-draft.php /absolute/or/relative/price.xlsx
php -d auto_prepend_file=src/load_env.php bin/import-draft.php /path/price.xlsx original-name.xlsx
```

Команда сама применяет миграции и пишет original в `storage/originals`. CLI-файл напрямую `src/load_env.php` не подключает, поэтому пример использует PHP `auto_prepend_file`. Альтернатива — заранее экспортировать все `MCV26_*` переменные в процесс. Не подключайте `.env` как shell-скрипт: DSN содержит `;`, а формат файла предназначен для `src/load_env.php`, не для Bash. Web endpoints загружают `.env` самостоятельно.

`bin/import-price.php` — legacy-команда немедленной файловой публикации и не является обычным DB upload workflow.
